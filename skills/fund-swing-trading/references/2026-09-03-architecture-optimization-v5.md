# 基金系统架构优化 v5.0 详细记录（09-03）

## 会话背景

用户指出系统架构问题："每次都要我主动叫你去检查和更新，好像我们的系统信息并不同步和关联一样"。用户希望"我只跟你说我都操作，然后其他的你自己去关联或更新"。

## 关键发现

### 1. 加权平均成本计算Bug

**问题**：`get_holdings()`使用最后一条记录的买入价，不是加权平均成本。

**影响**：
- 分批买入的基金（如017470：1000元@2.8526 + 300元@2.8242）
- 系统用2.8242计算市值，实际应使用加权均价2.8460
- 导致系统市值比支付宝高37元

**修复**：
```python
# 修复前
t.nav_price  # 取最后一条记录的买入价

# 修复后
SUM(amount * nav_price) / SUM(amount) as avg_cost  # 加权平均成本
```

**验证结果**：
- 修复前：系统市值4,528元，支付宝4,490元，差异37元
- 修复后：系统市值4,490元，支付宝4,490元，差异<0.01元

### 2. HTTP请求重复代码

**问题**：7个脚本都有重复的http函数。

**影响**：
- 修改HTTP逻辑需要改7个地方
- SSL配置可能不一致
- User-Agent可能不一致

**修复**：在`fund_common.py`中添加统一的`http_get()`函数。

### 3. 冗余脚本和表

**问题**：
- 1个脚本（fund_signal_engine.py）没有被任何脚本或cron任务使用
- 3张表（dragon_tiger、decisions、event_calendar）是空表

**修复**：
- 删除未使用的脚本
- 删除空表

## 关键学习点

### 1. 用户偏好：自动化同步
- 用户希望"只告诉我操作，其他自动同步"
- 不需要手动更新8处数据
- 系统自动验证数据一致性

### 2. 架构设计原则
- 单一数据源：所有数据从数据库读取
- 事件驱动：用户操作后自动同步
- 研究驱动：每个组件都产出研究成果
- 自动验证：完整性检查确保质量

### 3. 代码质量
- 消除重复代码
- 统一配置管理
- 统一错误处理
