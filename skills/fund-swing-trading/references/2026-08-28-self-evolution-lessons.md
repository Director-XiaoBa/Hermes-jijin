# 08-28 自进化框架 + 分析广度教训

## 三条学习线

用户明确要求三条线独立运行：
1. **我的预测** — 我做预测，我对我的预测负责，我验证我复盘我改进
2. **用户操作** — 用户参考我的分析但自己拍板，我只需要帮你验证对错
3. **老道推荐** — 我们跟踪他看他准不准，但不盲从

## 核心教训

### 08-27/08-28 追高买入教训
- **问题**：英伟达财报分析正确（存储弹性最大），但买入时机错误（大阳线日+4.5%追高）
- **根因**：只看了催化剂，没看宏观环境（杰克逊霍尔）+ A股位置（已暴涨）
- **修复**：分析范围四维度清单 + 买入时机铁律

### 用户纠正的关键点
1. "你不能光听我的" — 我必须有独立判断
2. "你是独立的个体" — 我的预测是我的，用户的操作是用户的
3. "预知和发现都要" — 日历预知 + 快讯发现 + 盘面反推，三层都要
4. "验证的是昨天的预测" — 15:50不验证当天预测，验证昨天的
5. "报告输出太少" — prompt必须明确指定输出格式和内容，不能让LLM自己决定推多少

### 数据源陷阱（08-28 发现）
- fundgz估值接口已死（08-24 SSL错误），天天基金下线净值估算
- pingzhongdata的净值是**上一交易日收盘值**，不是当天实时
- 14:00报告必须标注"净值截至上一交易日"，不能混为一谈
- 重仓股/ETF是实时数据（腾讯API），基金净值是T-1数据（天天基金API）——两者口径不同

## 数据表
- predictions — 我的预测记录
- improvement_log — 结构化改进清单
- monthly_stats — 月度统计
- kol_tracking — KOL跟踪
- trades.user_reasoning — 用户操作依据
- trades.analysis_scope — 买入时分析维度

## 自进化闭环
```
14:00预测 → predictions(pending)
15:50验证 → predictions(verified) + improvement_log
月底统计 → monthly_stats
月度调优 → 修改规则
```

## 分析范围四维度
每次建议前必须覆盖：①催化剂 ②宏观环境 ③A股位置 ④时机检查。缺一不可。

## 买入时机铁律
| 检查项 | 不通过=不买 |
|:--|:--|
| 大阳线日（板块涨>3%） | ❌ |
| 重大事件前夜 | ❌ |
| 连涨≥3天 | ❌ |
| 美股隔夜大涨 | ⚠️ |
