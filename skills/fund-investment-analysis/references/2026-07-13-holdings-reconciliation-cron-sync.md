# 2026-07-13 持仓对账 + 平安科技转换 + Cron Job 同步

## 背景
用户发送了支付宝基金持仓截图，要求对照台账对齐。截图显示仅有3只基金（无平安科技026211）。

## 发现的问题

### 1. 持仓不一致
| 台账记录的基金 | 截图实际持仓 | 差异 |
|:------------|:-----------|:----|
| 026211 平安科技（半仓） | ❌ 不存在 | 用户已在上周四(7/9)转换到半导体 |
| 014855 半导体增强（¥500买入） | ✅ 存在 ¥396.84 | 金额变了（含转换部分） |
| 017470 芯片ETF（¥1000买入） | ✅ 存在 ¥1452.52 | 金额变了（净值变动） |
| 021760 创新药（¥250买入） | ✅ 存在 ¥254.57 | 略涨 |

### 2. 平安科技转换细节
- **操作**：剩余半仓转换（转换）到 014855 半导体增强，非卖出
- **日期**：7/9（周四）操作，7/10（周五）结算
- **影响**：原实验A（平安科技留半仓 vs 换创新药）自动终止
- **更新动作**：台账删除026211，标记实验A终止

### 3. Cron Job 级联修复
台账更新后，检查所有定时任务：
- **每日基金任务（4个）**：动态 `cat` 台账文件 → 无需改动 ✅
- **实验结算任务（原 "平安科技卖一半vs留一半"）**：
  - ❌ prompt 中硬编码了实验A的平安科技描述
  - ❌ 原有一次性任务在我操作 `cronjob(action='run')` 时被消耗
  - ✅ 重建新的「基金实验B-创新药买入时机-结算」，仅保留实验B
  - ✅ `enabled_toolsets` 从 `["terminal"]` 升级到 `["terminal", "web"]`

### 4. 工具集权限修复（关键！）
半导体科技基金每日新闻情报的 `enabled_toolsets` 只有 `["web"]`，缺少 `terminal`，导致：
- 读不了本地台账文件（需要 `terminal` 执行 `cat`）
- 跑不了 `curl` 获取实时基金估值
- 做不了任何 shell 命令

**修复**：`["web"]` → `["terminal", "web"]`
**根因**：创建任务时漏配了 `terminal`，其他基金任务（14:00/14:45/21:30）都有 `["terminal", "web"]` 但这个没有。

### 5. 全量 prompt 同步（不只是实验任务）
用户指出"还有几个基金任务"，说明光改实验任务不够。最终更新了 **4个基金任务的 prompt**：

| 任务 | 修改点 |
|:----|:-------|
| 半导体科技基金每日新闻情报 (10:00) | 工具集修复 + prompt末尾明确3只持仓 |
| 基金14点AI综合研判 (14:00) | prompt末尾加"平安科技已清仓，仅3只" |
| 基金盘中估值+AI分析 (14:45) | 同上 |
| 基金晚间净值复盘 (21:30) | 同上 |
| 周末持仓复盘周报 (周六) | 硬编码的用户描述更新为3只持仓 |
| 实验B结算 (7/14 20:00) | 重建，只保留实验B |

**关键模式**：修改任务时，列出受影响的全部同类任务，逐个检查，一个不漏。

### 6. prompt 优化技巧
在每个基金任务 prompt 末尾加一句明确说明，帮助任务运行时正确聚焦：
```
用户是普通上班族，在海口，UTC+8，全中文回复。目前只有3只基金持仓（017470、014855、021760），平安科技已清仓。
```
这比仅靠"动态读取台账"更可靠——当任务中的 AI 刚开始执行时就能知道要查哪些基金。

## 经验教训
1. 用户分享持仓截图时，不仅要更新台账数字，还要**逐只基金核对是否存在差异**
2. 持有基金的名称和数量变化（转换/清仓）必须同步到相关 cron job
3. 实验结算任务可能硬编码基金名称，台账变更后需手动重建
4. 一次性 cron job 被 `action=run` 触发后会消耗掉，需重新创建
5. **创建基金 cron job 时必须配 `["terminal", "web"]`**，缺 `terminal` 会导致无法读取文件和执行数据采集命令
6. **先列出所有受影响的任务再动手**，而不是修完一个再等用户提醒"还有几个"
7. Prompt 末尾加"当前XX只基金，XXX已清仓"的明确说明，帮助任务中的 AI 快速聚焦
